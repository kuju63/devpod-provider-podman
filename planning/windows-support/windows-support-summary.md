# Windows対応計画サマリー

## 概要

DevPod Podman ProviderをWindows 11環境に対応させるための計画書です。このドキュメントは、3つの詳細ドキュメントのエグゼクティブサマリーとして機能します。

## 対応範囲

### 対象環境
- **OS**: Windows 11（22H2以降）
- **Podman**: Podman Desktop 1.0以降、またはPodman CLI 4.0以降
- **バックエンド**: WSL2（Windows Subsystem for Linux 2）
- **シェル**: Git Bash（MSYS2）またはWSL内のbash

### 除外する環境
- Windows 10（WSL2の安定性の観点から）
- Hyper-Vバックエンド（WSL2がデフォルトかつ推奨）
- PowerShell/CMD直接実行（DevPodのプロバイダーモデルの制約）

## 技術的アプローチ

### 基本方針

**既存のmacOS用Machine管理ロジックを流用**

Windows版PodmanもmacOSと同様にPodman Machineを使用するため、既存のロジックをほぼそのまま適用可能。主な変更点は：

1. **プラットフォーム判定の追加**
   - `$OSTYPE`変数による3プラットフォーム判定（macOS/Windows/Linux）
   - Windows判定: `msys`または`cygwin`

2. **エラーメッセージのプラットフォーム対応**
   - インストール手順をプラットフォーム別に表示
   - Windows: Podman Desktop推奨、wingetコマンド提示

3. **デフォルトマシン名の調整**
   - Windows: `podman-machine-default`（Podman Desktopのデフォルト）
   - macOS: `devpod-machine`（カスタム名）

### 実装の複雑さ

**低〜中程度**

- 新規機能の追加ではなく、既存機能の拡張
- プラットフォーム判定ロジックの追加が主な変更
- 既存のbash構文をそのまま使用可能（Git Bash前提）

## 主要なリスク

### 高リスク

#### R-1: DevPodのシェル実行環境が不明
**影響**: 実装方針が大きく変わる可能性

**対策**:
- Phase 0でDevPodのソースコード確認
- 実機テストでの確認
- 複数のシェル環境で動作する汎用実装

**判断基準**:
- Git Bash使用 → 実装継続
- WSL bash使用 → 判定方法の見直し
- PowerShell使用 → 大幅な設計変更

#### R-2: Podman DesktopとCLIの動作差異
**影響**: 一部の環境で動作しない可能性

**対策**:
- 両環境でのテスト実施
- 推奨環境の明記（Podman Desktop優先）
- 既知の問題のドキュメント化

### 中リスク

#### R-3: WSL2環境の多様性
**対策**: 最小限の前提条件、診断情報の充実

#### R-4: JSON解析の互換性
**対策**: 既存のgrep/awk方式を維持、必要に応じてjqフォールバック

## まとめ

Windows対応は、以下の理由により実現可能性が高い：

1. **技術的な実現可能性**
   - Podman MachineがWindows（WSL2）でも動作
   - macOSと同じコマンド体系
   - 既存のbash構文を流用可能

2. **実装の複雑さが低い**
   - 新規機能ではなく既存機能の拡張
   - プラットフォーム判定の追加が主な変更
   - 約15行のコード追加で基本機能が実現

3. **段階的なアプローチ**
   - Phase 0で技術的不確実性を解消
   - Phase 1-2で段階的に実装
   - Phase 3で完全なテストとドキュメント
